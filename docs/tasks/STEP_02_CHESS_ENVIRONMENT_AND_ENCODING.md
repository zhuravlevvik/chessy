## 1. Цель задачи

Реализовать проверяемый фундамент для всех следующих компонентов Chessy:

- тонкую шахматную среду поверх `python-chess` для стандартных шахмат;
- версионированное представление позиции `board119-v1`;
- версионированное пространство действий `az73-v1` из 4672 действий;
- маску легальных действий;
- взаимно-однозначное преобразование легального хода между `chess.Move`, UCI и
  action index;
- быстрые unit- и perft-тесты.

После выполнения шага любой легальный ход в поддерживаемой позиции должен
кодироваться в один индекс, декодироваться обратно без потерь и однозначно
отмечаться в legal mask. Позиция с историей должна преобразовываться в
детерминированный массив формы `[119, 8, 8]`.

Задача не включает нейросеть, PyTorch, MCTS, self-play, обучение, конфигурацию
run, API или пользовательский интерфейс.

## 6. Шахматная среда

### 6.1. Общий принцип

`ChessEnvironment` в `src/chessy/chess/environment.py` — небольшая обёртка над
`chess.Board`, а не альтернативная реализация правил.

Среда должна владеть доской и сохранять полный move stack. Он необходим для
истории `board119-v1`, повторений, правила 50 ходов и построения PGN.

Минимальный публичный контракт:

```python
class ChessEnvironment:
    @classmethod
    def from_fen(cls, fen: str) -> "ChessEnvironment": ...

    @property
    def board(self) -> chess.Board: ...

    def reset(self) -> None: ...
    def copy(self) -> "ChessEnvironment": ...
    def legal_moves(self) -> tuple[chess.Move, ...]: ...
    def push(self, move: chess.Move) -> None: ...
    def push_uci(self, uci: str) -> chess.Move: ...
    def fen(self) -> str: ...
    def is_terminal(self) -> bool: ...
    def outcome(self) -> chess.Outcome | None: ...
    def terminal_value(self, perspective: chess.Color) -> float: ...
    def history(self, length: int = 8) -> tuple[chess.Board, ...]: ...
```

Допустим эквивалентный компактный API, если вся семантика ниже соблюдена и
тесты используют только публичные функции.

### 6.2. Инварианты среды

- Конструктор без аргументов создаёт начальную позицию.
- Входная доска при передаче копируется с `stack=True`, чтобы внешняя мутация не
  меняла среду.
- `board` не должен позволять незаметно разрушить внутренние инварианты. Лучше
  возвращать копию; если возвращается внутренний объект, это решение и риски
  нужно явно описать в docstring.
- `push` принимает только легальный ход и выбрасывает `ValueError` для
  нелегального.
- `push_uci` парсит UCI в контексте текущей позиции, проверяет легальность,
  применяет ход и возвращает канонический `chess.Move`.
- `copy` создаёт независимую среду с сохранённой историей.
- Терминальность и исход определяются через `python-chess` с
  `claim_draw=True`, чтобы учитывать доступную ничью по троекратному повторению
  и правилу 50 ходов.
- `terminal_value(perspective)` возвращает `+1.0` при победе указанного цвета,
  `-1.0` при поражении и `0.0` при ничьей. Для нетерминальной позиции функция
  выбрасывает `ValueError`, а не возвращает фиктивное значение.
- `history(8)` возвращает доски в порядке «текущая, один полуход назад, ...».
  Каждая доска должна иметь корректную историю именно на тот момент.
- Если фактической истории меньше запрошенной длины, список дополняется копиями
  самой ранней доступной позиции.
- `from_fen` начинает новую историю из одной позиции: прошлые позиции из одного
  FEN восстановить невозможно.

### 6.3. Сериализация

В этом шаге обязательны FEN и UCI. Полноценный PGN-export можно добавить только
если он остаётся тонкой функцией поверх move stack и покрыт тестом. Метаданные
игроков, часов и источников партии не входят в задачу.

## 7. Perft

В `src/chessy/chess/perft.py` реализовать чистую функцию:

```python
def perft(board: chess.Board, depth: int) -> int: ...
```

Требования:

- `depth < 0` выбрасывает `ValueError`;
- `depth == 0` возвращает `1`;
- функция не изменяет переданную доску, включая её FEN и move stack;
- рекурсия использует `push`/`pop`, без копирования доски на каждую ветвь;
- никакой оптимизации, кеша или многопоточности пока не требуется.

Обязательные эталонные тесты:

| Позиция | Depth | Nodes |
|---|---:|---:|
| Начальная | 1 | 20 |
| Начальная | 2 | 400 |
| Начальная | 3 | 8902 |
| Kiwipete | 1 | 48 |
| Kiwipete | 2 | 2039 |
| Kiwipete | 3 | 97862 |

FEN Kiwipete:

```text
r3k2r/p1ppqpb1/bn2pnp1/3PN3/1p2P3/2N2Q1p/PPPBBPPP/R3K2R w KQkq - 0 1
```

Также проверить, что после `perft` исходная доска не изменилась.

## 8. Контракт `board119-v1`

### 8.1. Форма, dtype и ориентация

В `src/chessy/encoding/board.py` определить:

```python
BOARD_ENCODING_VERSION = "board119-v1"
BOARD_PLANES = 119
HISTORY_LENGTH = 8
```

Основная функция:

```python
def encode_board(history: Sequence[chess.Board]) -> np.ndarray: ...
```

Допустима удобная обёртка `encode_environment(environment)`, но единственный
источник семантики должен оставаться в `encode_board`.

Результат:

- форма `[119, 8, 8]`, без batch dimension;
- dtype `np.float32`;
- C-contiguous array;
- абсолютная ориентация для обоих цветов;
- координата массива для поля: `[plane, rank, file]`, где `a1 -> [0, 0]`,
  `h8 -> [7, 7]`;
- значения бинарных плоскостей только `0.0` или `1.0`;
- функция не мутирует входные доски.

Batch dimension будет добавляться collate-функцией на следующих этапах.

### 8.2. Порядок истории

`history[0]` — текущая позиция, `history[1]` — позиция один полуход назад и так
далее. Используются максимум восемь элементов.

Если элементов меньше восьми, недостающие состояния заполняются повторением
самой ранней переданной позиции. Пустая последовательность недопустима и должна
вызывать `ValueError`.

### 8.3. Точное распределение плоскостей

Каждое историческое состояние занимает 14 плоскостей:

```text
history_offset = history_index * 14
```

Внутри состояния:

| Offset | Содержимое |
|---:|---|
| 0 | белые пешки |
| 1 | белые кони |
| 2 | белые слоны |
| 3 | белые ладьи |
| 4 | белые ферзи |
| 5 | белый король |
| 6 | чёрные пешки |
| 7 | чёрные кони |
| 8 | чёрные слоны |
| 9 | чёрные ладьи |
| 10 | чёрные ферзи |
| 11 | чёрный король |
| 12 | позиция встречалась ранее хотя бы один раз |
| 13 | позиция встречалась ранее хотя бы два раза |

Плоскости повторения полностью заполняются единицами при выполнении условия,
иначе нулями. Условия вычисляются для конкретного исторического состояния по
его собственному сохранённому move stack:

- offset 12 соответствует `board.is_repetition(2)`;
- offset 13 соответствует `board.is_repetition(3)`.

Итого история занимает плоскости `0..111`.

Служебные плоскости берутся только из текущей позиции `history[0]`:

| Plane | Содержимое |
|---:|---|
| 112 | сторона хода: единицы для белых, нули для чёрных |
| 113 | право белых на короткую рокировку |
| 114 | право белых на длинную рокировку |
| 115 | право чёрных на короткую рокировку |
| 116 | право чёрных на длинную рокировку |
| 117 | `min(halfmove_clock, 100) / 100.0` по всей плоскости |
| 118 | one-hot поле en passant |

Для en passant использовать `board.ep_square` как состояние позиции. Не
заменять его проверкой наличия конкретного легального взятия. При отсутствии
поля вся плоскость равна нулю.

Halfmove clock ограничивается сверху единицей. Отрицательное значение не должно
возникать в валидном `python-chess`, но защитная проверка допустима.

### 8.4. Обязательные тесты позиции

Проверить:

1. Форму, dtype, contiguous layout и диапазон значений.
2. Точные поля всех фигур в начальной позиции.
3. Белую сторону хода и четыре права рокировки в начале партии.
4. Чёрную сторону хода после `e2e4` без переворота доски.
5. En passant после двойного хода пешки и нулевую плоскость без него.
6. Нормализацию halfmove clock для `0`, промежуточного значения, `100` и
   значения больше `100`.
7. Снятие каждого отдельного права рокировки.
8. Порядок текущей и предыдущих позиций после нескольких ходов.
9. Padding ранней позицией в начале партии.
10. Плоскости двукратного и троекратного повторения на цикле ходов коней.
11. Детерминизм: одинаковый вход даёт побитово одинаковый массив.
12. Отсутствие мутации досок и их move stack.
13. Ошибку на пустой истории.

## 9. Контракт `az73-v1`

### 9.1. Основные константы и API

В `src/chessy/encoding/action.py` определить:

```python
ACTION_ENCODING_VERSION = "az73-v1"
ACTION_PLANES = 73
ACTION_SIZE = 4672
```

Публичный API:

```python
def encode_move(board: chess.Board, move: chess.Move) -> int: ...
def decode_action(board: chess.Board, action: int) -> chess.Move: ...
def legal_action_mask(board: chess.Board) -> np.ndarray: ...
```

Допустимы небольшие публичные helpers для `plane/from_square`, если они нужны
другим компонентам, но не создавать абстрактную иерархию кодировщиков.

### 9.2. Общий индекс

```text
action = plane * 64 + from_square
```

Нумерация полей берётся из `python-chess`: `a1 = 0`, `h8 = 63`.

Проверки:

- action должен находиться в `[0, 4672)`;
- `encode_move` принимает только ход, легальный на переданной доске;
- `decode_action` возвращает только легальный ход в переданной позиции;
- некорректный индекс, невозможная геометрия и нелегальный ход дают понятный
  `ValueError`.

### 9.3. Плоскости 0–55: линейные ходы

Порядок абсолютных направлений фиксирован:

| Direction index | Название | `(df, dr)` |
|---:|---|---|
| 0 | north | `(0, +1)` |
| 1 | north-east | `(+1, +1)` |
| 2 | east | `(+1, 0)` |
| 3 | south-east | `(+1, -1)` |
| 4 | south | `(0, -1)` |
| 5 | south-west | `(-1, -1)` |
| 6 | west | `(-1, 0)` |
| 7 | north-west | `(-1, +1)` |

Для расстояния `1..7`:

```text
plane = direction_index * 7 + (distance - 1)
```

Сюда входят ходы ладьи, слона, ферзя, короля, пешки, рокировка, en passant и
превращение в ферзя. При декодировании линейного хода пешки на последнюю
горизонталь нужно восстановить `promotion=chess.QUEEN`.

### 9.4. Плоскости 56–63: кони

Порядок смещений фиксирован:

| Plane | `(df, dr)` |
|---:|---|
| 56 | `(+1, +2)` |
| 57 | `(+2, +1)` |
| 58 | `(+2, -1)` |
| 59 | `(+1, -2)` |
| 60 | `(-1, -2)` |
| 61 | `(-2, -1)` |
| 62 | `(-2, +1)` |
| 63 | `(-1, +2)` |

### 9.5. Плоскости 64–72: underpromotion

Только превращения в коня, слона и ладью получают специальные плоскости.

Порядок фигур:

```text
0 = knight, 1 = bishop, 2 = rook
```

Порядок направлений относительно движущегося игрока:

```text
0 = forward-left capture
1 = forward
2 = forward-right capture
```

Формула:

```text
plane = 64 + promotion_piece_index * 3 + relative_direction_index
```

«Left» и «right» определяются с точки зрения игрока, смотрящего в сторону
превращения:

| Цвет | forward-left | forward | forward-right |
|---|---|---|---|
| белые | `(-1, +1)` | `(0, +1)` | `(+1, +1)` |
| чёрные | `(+1, -1)` | `(0, -1)` | `(-1, -1)` |

Цвет и точная геометрия восстанавливаются из `board.turn` и фигуры на
`from_square`. Поэтому декодирование action всегда требует текущую доску.

### 9.6. Рокировка и en passant

- В стандартных шахматах рокировка кодируется обычным ходом короля `e1g1`,
  `e1c1`, `e8g8` или `e8c8` в линейной плоскости.
- En passant кодируется обычным диагональным перемещением пешки.
- Специальных action planes для них нет.
- Chess960-форма рокировки не поддерживается.

### 9.7. Legal mask

`legal_action_mask(board)` возвращает:

- форму `[4672]`;
- dtype `np.bool_`;
- C-contiguous array;
- `True` ровно для индексов из `board.legal_moves`;
- полностью нулевую маску для терминальной позиции без легальных ходов.

Маска строится перечислением легальных ходов и вызовом единого
`encode_move`. Не дублировать геометрию кодировщика отдельной реализацией.

Количество `True` обязано совпадать с `board.legal_moves.count()`. Если два
разных легальных хода неожиданно получили один индекс, выбрасывать ошибку в
debug/test-контексте; тесты должны доказывать отсутствие коллизий.

### 9.8. Обязательные тесты действий

1. Точные индексы нескольких простых ходов из начальной позиции, включая ход
   пешки на одно/два поля и ход коня.
2. Round-trip для всех легальных ходов начальной позиции.
3. Round-trip для всех легальных ходов Kiwipete.
4. Обе рокировки обоих цветов.
5. En passant за белых и чёрных.
6. Все четыре превращения (`Q`, `R`, `B`, `N`) без взятия за оба цвета.
7. Все четыре превращения со взятием в обе стороны за оба цвета.
8. Отсутствие коллизий и полный round-trip на детерминированной выборке минимум
   из 100 достижимых позиций, полученных random playout с фиксированным seed.
9. Legal mask: форма, dtype, число единиц и соответствие каждому легальному
   ходу.
10. Полностью пустая маска в позиции мата и пата.
11. Ошибки для action `< 0`, `>= 4672`, нелегального хода и индекса, который не
    соответствует легальному ходу в данной позиции.
12. Детерминизм и отсутствие мутации `board`/move stack.

Random playout в тесте не должен проверять силу игры. На каждом шаге выбирать
ход из стабильного списка, отсортированного по UCI, с генератором, созданным из
фиксированного seed.

## 10. Экспорты пакетов

В `src/chessy/chess/__init__.py` и `src/chessy/encoding/__init__.py` экспортировать
только устойчивый публичный API и версии контрактов. Не использовать wildcard
imports.

Корневой `src/chessy/__init__.py` сохраняет версию проекта `0.1.0`. Повышение
версии проекта в этом шаге не требуется.

## 11. Требования к качеству реализации

- Вся арифметика файлов и горизонталей должна проверять границы `0..7`, чтобы
  ход не «оборачивался» через край доски.
- Не кодировать направление через разность сырых square indices без отдельной
  проверки file/rank: это легко создаёт ложные ходы на краях.
- Для action encoding использовать одну таблицу направлений как источник
  истины для encode и decode.
- Не полагаться на порядок итерации `legal_moves` в тестах.
- Не сравнивать NumPy-массивы через обычный `==` в boolean-контексте.
- Ошибки публичного API должны быть `ValueError` с контекстом позиции/хода или
  индекса, но без огромных дампов массивов.
- Не оптимизировать преждевременно. Корректность и ясный контракт важнее
  микросекунд на этом этапе.

## 12. Порядок реализации

1. Проверить чистоту рабочей директории и зафиксировать исходный `git status`.
2. Прочитать архитектурные документы.
3. Добавить NumPy и pytest через `uv`, обновить lock-файл.
4. Создать пакет `chessy.chess` и тесты среды.
5. Реализовать и проверить perft.
6. Создать `board119-v1` с точными константами и тестами каждой группы
   плоскостей.
7. Создать `az73-v1`, сначала линейные и конные ходы, затем promotions.
8. Добавить legal mask и exhaustive round-trip тесты.
9. Запустить весь test suite.
10. Выполнить финальные проверки lock-файла, импортов и Git diff.

Не оставлять тесты «на потом»: для action encoding они являются частью самого
контракта.

uv lock --check

## 14. Критерии приёмки

Задача считается выполненной, только если одновременно выполнено всё ниже:

- [ ] NumPy объявлен runtime-зависимостью, pytest — dev-зависимостью.
- [ ] `uv.lock` актуален, `uv lock --check` и `uv sync --locked` проходят.
- [ ] Среда применяет только легальные ходы и сохраняет move stack.
- [ ] Мат, пат, недостаточный материал, троекратное повторение и правило 50
      ходов корректно распознаются через `python-chess`.
- [ ] Terminal value корректен с точки зрения обоих цветов.
- [ ] Perft совпадает с эталонными значениями для начальной и Kiwipete-позиции.
- [ ] `board119-v1` имеет точную форму `(119, 8, 8)` и dtype `float32`.
- [ ] Все номера и значения 119 плоскостей соответствуют разделу 8.
- [ ] История идёт от текущей позиции назад и корректно дополняется.
- [ ] Повторения, рокировки, halfmove clock и en passant покрыты тестами.
- [ ] `az73-v1` содержит ровно 4672 действия с утверждённым порядком 73
      плоскостей.
- [ ] Линейные ходы, кони, рокировки, en passant и все promotions проходят
      round-trip.
- [ ] Каждый легальный ход в тестовой выборке получает уникальный индекс.
- [ ] Legal mask имеет форму `(4672,)`, dtype `bool` и точно совпадает со
      множеством легальных ходов.
- [ ] Нелегальные ходы и действия отклоняются понятной ошибкой.
- [ ] Кодирование детерминировано и не мутирует входные доски.
- [ ] Все тесты проходят одной командой `uv run pytest`.
- [ ] `git diff --check` не находит ошибок форматирования.
- [ ] Файлы в `data/` не изменены.
- [ ] PyTorch, MCTS, модель, API и UI не добавлены преждевременно.

## 15. Что не делать даже при наличии времени

- Не реализовывать batch encoder, DataLoader и чтение personal dataset.
- Не переносить кодирование на GPU/MPS.
- Не добавлять симметрии и геометрические аугментации.
- Не добавлять Chess960.
- Не создавать policy/value network.
- Не реализовывать softmax или применение `-inf`; задача этого шага — вернуть
  корректную boolean mask.
- Не писать собственный генератор легальных ходов.
- Не проводить бенчмарки силы или обучение.
