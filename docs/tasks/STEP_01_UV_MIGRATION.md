# Chessy — шаг 1: миграция на uv и pyproject.toml

Статус: готово к реализации

## 1. Цель задачи

Перевести существующий Python-код Chessy с ручного `requirements.txt` и
самостоятельно созданной `.venv` на воспроизводимый проект под управлением `uv`.

После выполнения задачи проект должен использовать:

- Python 3.12;
- `uv` как менеджер проекта и зависимостей;
- локальное виртуальное окружение `.venv`;
- `pyproject.toml` как единственный декларативный источник Python-зависимостей;
- `uv.lock` как точную фиксацию разрешённых версий;
- минимальный installable package в `src/chessy/`;
- запуск существующих скриптов через `uv run`.

Задача не включает реализацию шахматной среды, модели, MCTS, обучения, API или
интерфейса.

## 2. Архитектурное решение

Решение уже утверждено и описано в:

- `docs/decisions/0001-python-packaging.md`;
- разделе 22 файла `docs/PROJECT_PLAN.md`.

Нельзя заменять `uv` на Poetry, Conda, pip-tools, Hatch environments или другой
менеджер окружений. Build backend может использовать Hatchling, но управление
проектом и lock-файлом остаётся за `uv`.

## 3. Текущее состояние проекта

Перед изменениями агент обязан самостоятельно проверить фактическое состояние,
но ожидается следующее:

- в корне есть `requirements.txt`;
- текущая зависимость в нём: `python-chess==1.999`;
- существует локальная `.venv` на Python 3.12;
- `.venv/` уже исключена в `.gitignore`;
- Python-скрипты находятся в `scripts/`;
- скрипты подготовки данных уже используются и должны продолжить работать;
- директория `src/chessy/` пока отсутствует;
- Git-репозиторий может быть не инициализирован;
- данные в `data/` являются результатом длительной подготовки и не должны быть
  изменены.

Существующие скрипты:

- `scripts/export_games.py`;
- `scripts/filter_quality_games.py`;
- `scripts/select_quality_games.py`;
- `scripts/build_personal_dataset.py`;
- `scripts/split_personal_dataset.py`.

## 4. Обязательные ограничения

1. Не удалять и не перегенерировать файлы в `data/`.
2. Не запускать полный Stockfish-анализ партий.
3. Не выполнять сетевую выгрузку Chess.com или Lichess.
4. Не инициализировать Git без отдельного запроса пользователя.
5. Не добавлять PyTorch, FastAPI, UI-зависимости или библиотеки будущих этапов.
6. Не обновлять Homebrew, Python или глобальные пакеты без необходимости.
7. Не сохранять `.venv` в репозитории.
8. Не поддерживать одновременно ручной `requirements.txt` и `uv.lock` после
   успешного завершения миграции.
9. Существующие данные и скрипты пользователя нужно сохранить.
10. Все изменения файлов выполнять аккуратно и только в рамках этой задачи.

После миграции минимальная структура должна выглядеть так:

Создание развитой структуры модулей и `tests/` относится к следующему шагу.
В этой задаче создаётся только минимальный пакет, необходимый для корректной
установки проекта.

## 7. Требования к pyproject.toml

`pyproject.toml` должен содержать как минимум:

- имя проекта `chessy`;
- начальную версию `0.1.0`;
- краткое описание;
- ограничение Python `>=3.12,<3.13`;
- runtime-зависимость `python-chess==1.999`;
- build system для `src`-layout;
- корректное указание пакета `src/chessy`.

Рекомендуемый build backend: Hatchling.

Ориентировочная конфигурация:

```toml
[project]
name = "chessy"
version = "0.1.0"
description = "A personal self-learning and personalized chess bot"
requires-python = ">=3.12,<3.13"
dependencies = [
  "python-chess==1.999",
]

[build-system]
requires = ["hatchling"]
build-backend = "hatchling.build"

[tool.hatch.build.targets.wheel]
packages = ["src/chessy"]
```

Это ориентир, а не разрешение добавлять лишние зависимости. Если актуальный
`uv` создаёт эквивалентную корректную конфигурацию, допустим небольшой
синтаксический вариант.

Не добавлять `readme = ...`, если соответствующий файл не существует и агент не
создаёт его осознанно в рамках минимальной упаковки.

## 8. Версия Python

Создать `.python-version` со значением:

```text
3.12
```

После этого `uv` должен выбирать Python 3.12 для локального окружения.

Не фиксировать patch-версию вроде `3.12.11`, если для этого нет технической
необходимости: проект утверждён на линии Python 3.12.

## 9. Минимальный пакет

Создать:

```text
src/chessy/__init__.py
```

Файл должен быть минимальным. Допустимо объявить:

```python
"""Chessy personal chess bot."""

__version__ = "0.1.0"
```

Не создавать заглушки для модели, MCTS, API и других будущих компонентов.

## 10. Создание lock-файла и окружения

После создания `pyproject.toml` и `.python-version`:

1. Выполнить разрешение зависимостей и создать `uv.lock`.
2. Синхронизировать локальную `.venv`.
3. Убедиться, что используется Python 3.12.

Предпочтительные команды:

```bash
uv lock
uv sync
uv run python --version
```

Существующая `.venv` считается расходным локальным окружением. Не удалять её
вручную без необходимости: сначала дать `uv sync` привести окружение к целевому
состоянию. Если `uv` обоснованно не может использовать существующую `.venv`,
разрешается пересоздать только `.venv`, не затрагивая другие файлы.

## 11. Миграция requirements.txt

Удалить `requirements.txt` только после того, как выполнены все условия:

1. `python-chess==1.999` объявлен в `pyproject.toml`.
2. `uv.lock` успешно создан.
3. `uv sync` успешно завершён.
4. `uv run python -c "import chess"` работает.
5. Help-команды существующих скриптов работают через `uv run`.

После этого `requirements.txt` становится дублирующим источником и должен быть
удалён.

## 12. Проверка существующих скриптов

Не запускать тяжёлую бизнес-логику. Проверить только импорт и CLI parsing:

```bash
uv run python scripts/export_games.py --help
uv run python scripts/filter_quality_games.py --help
uv run python scripts/select_quality_games.py --help
uv run python scripts/build_personal_dataset.py --help
uv run python scripts/split_personal_dataset.py --help
```

Help-команды не должны выполнять сетевые запросы, Stockfish-анализ или менять
датасеты.

Дополнительная проверка пакета:

```bash
uv run python -c "import chess; import chessy; print(chess.__version__, chessy.__version__)"
```

Ожидается успешный импорт `chess` и `chessy`.

## 13. Проверки lock-файла

Выполнить:

```bash
uv lock --check
uv sync --locked
```

После `uv sync --locked` рабочее дерево не должно получать неожиданных изменений
в `uv.lock` или `pyproject.toml`.

Проверить дерево зависимостей:

```bash
uv tree
```

В runtime-графе должны присутствовать `python-chess` и его пакет `chess`.
Будущих ML/API/UI-зависимостей быть не должно.
